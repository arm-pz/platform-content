# Formats

Per-platform structure. Read the section for the asset you are writing, plus the hooks and CTA
patterns at the end. Nothing here is a claim about how a ranking system works; where a platform's
behaviour is mentioned it is something commonly reported, and the asset should be written so the
user can test it.

## How to use this file

1. Pick the platform section. Copy its structure, do not improvise a generic post.
2. Choose a hook type from the hook list, then write the body that pays it off.
3. Write one call to action from the CTA patterns, with what happens next for the reader.
4. Fill any figure with the user's number or `[metric — supply this]`. Never a plausible guess.

## Hook types (shared vocabulary)

A hook is a promise about what the reader gets if they keep going. Use the same name for it in a
calendar row so the mix is visible.

- **Problem-first.** Name the reader's situation in their words. "You rewrote the opening four times and it still reads flat."
- **Outcome-first.** State the result the piece shows how to reach, without a number you do not have.
- **Count stack.** A list the body actually delivers: "three checks", "seven questions". The count must match the asset, and it counts your own structure, not a performance statistic.
- **Contrarian.** Name the common advice and say why the piece argues against it. Only when the body makes the case.
- **Open loop.** Start mid-story, resolve it later. Works in video and newsletter openings; keep the loop short or it reads as evasion.
- **Callout.** Address who the asset is for, and by omission who it is not for. "If you publish weekly and nothing compounds, this is for you."
- **Specific detail.** One concrete, verifiable thing from the user's own material beats any tease. Use it when they supplied one.
- **Question.** Only when the reader already has the question. Otherwise it sounds like a headline generator.

Rules: the hook carries the entire job in the space before a fold or a tap (line one, the first
three seconds, the subject line). No hook may promise a payoff the body does not deliver. No hook
may assert a result ("this will double your reach").

## Twitter/X thread

Shape, one idea per post:

1. **Hook post.** The promise, standalone, no "thread below" throat-clearing. If a reader sees only this, it should still be worth a bookmark.
2. **Contract post.** One or two lines on what the thread covers and why the user is the one saying it, using only the credentials the user supplied.
3. **Value posts.** Each makes one point in its own words, with a small heading or numbered lead so it survives being read out of order. Concrete over abstract: an example, a line from the work, a check to run.
4. **Recap post.** The points in one block, or the single takeaway restated.
5. **CTA post.** One action.

Thread rules: keep each post under the platform's length limit and check the break points after editing, since a mid-sentence wrap reads as noise. Write the thread in reading order with no cliffhanger that forces the whole scroll for a single point; a reader who stops at post 4 should still have got value. Attach media only where the user has it. Link placement: commonly reported that a link in the first post costs reach; treat that as a test, not a rule, and offer a link-in-reply variant.

Retention beats for a thread: value in the first two posts, one new thing per post, no repeated point, the recap before the ask.

## LinkedIn post

Structure:

```
<line one hook, no preamble>
<blank>
<context: the situation in one or two short lines>
<the beats: one idea per line or short paragraph, white space between>
<the takeaway in one line a reader could quote>
<CTA>
```

Craft notes: the two lines before the fold carry the whole job, so write them last and cut any lead-in such as "I am delighted to share". Short lines, hard returns, no wall. Authority comes from specificity and from what the user has done, never from credential inflation or a lesson the user did not learn. Skip the three-dot filler and the manufactured humility. Personal framing works when the post has one real detail from the user; without it, write it as direct advice instead.

For a lead goal, name who the post is for and what the reader gets by replying or clicking, then offer the comment variant: some accounts report better conversation in comments, so write the same CTA both in-post and as a first comment and let the user compare.

## YouTube script

Written as spoken text. Mark every section with an approximate timestamp and a visual note; the
script is for the edit as well as the recording.

```
COLD OPEN (first 30 seconds)   Restate the promise in plain words, add the stake, say what the
                               viewer gets by staying. No channel history, no long intro music.
ROADMAP                        The sections by name, so the viewer knows what a finish looks like.
SECTION 1..N                   One idea each. End each section with a re-hook that opens the next
                               ("which brings us to the part that trips most people up").
PROOF                          The demo, the example, the worked case. Slot for anything the user
                               has not supplied: [footage — supply this].
PAYOFF                         Deliver the promised result before asking for anything.
CTA / END SCREEN               One ask, tied to what the viewer just got.
```

Retention beats: re-hooks at section ends, no filler that a viewer can skip and lose nothing,
open a question early and close it late, cut the recap that repeats rather than the one that
reframes. Keep the promise of the title and thumbnail exactly matched by the cold open; a mismatch
is the defect, not the viewer. Note B-roll and on-screen text where the sentence needs help, and
write the title and the thumbnail idea alongside the script so the package is testable as one unit.

## Short-form script (TikTok, Reels, Shorts)

Two columns, one idea per shot, roughly 30 seconds when the brief says 30 seconds.

```
0-3s    HOOK      Spoken line plus the on-screen text. Says who it is for and what they get.
3-8s    SETUP     The one piece of context the body needs. Nothing else.
8-24s   BEATS     Two or three steps or points. One action per line, each matched by a visual.
24-30s  PAYOFF    The result or the single takeaway, restated in the words used in the hook.
END     LOOP      A last line that lands the viewer back at the start, or the CTA, not both.
```

Craft notes: write for sound-off viewing, so on-screen text carries the point as well as the voice.
Short sentences, no subordinate clauses, no "in this video I will". Keep captions verbatim to what
is spoken. Completion rate is commonly reported as the signal short-form platforms reward, so write
for the last line rather than the first and treat the length as a variable the user can test: cut
five seconds and compare.

## Instagram caption

Opening-line types (the line shown before "more"): question the reader already has, a blunt
statement of the point, a number from the user's own work, a "save this for..." line when the
caption really is a reference, a mid-story line. Avoid the tease that the caption never collects.

```
OPENING LINE        One line, no emoji, no hashtag.
BODY                Two to five short paragraphs, or a bulleted list if the caption teaches.
CTA                 One action: comment a word, save it, tap the link in bio, follow for the series.
HASHTAG SLOTS       A handful of specific tags tied to the post, not a block of generic ones.
LINK                [link-in-bio target — supply this] if the CTA needs one.
```

Caption craft: the caption must work with the visual rather than describe it. Do not repeat what the
image already says; add the context, the step or the reason. For a reel, write the caption assuming
the viewer came from the video, so the opening line extends it instead of restarting it.

## Newsletter issue

```
SUBJECT             Three options: one plain, one specific, one curiosity. Each must be true.
PREVIEW TEXT        The line that finishes the subject, not a repeat of it.
OPENING             Two or three lines: what this issue is and why now. No housekeeping at the top.
BODY                One main section, then shorter ones. A subheading every few hundred words so a
                    skimmer keeps the thread.
CTA                 One ask, with what the reader gets from it.
POSTSCRIPT          The extra link, the correction or the human line.
```

Craft notes: subject line and first sentence must match the content exactly, otherwise the open rate
learned from it is worthless. Write it as a letter to one named reader, in the user's own register.
A forward is a consequence of an issue being useful to someone else, so make the ask honest and
specific ("send this to the person on your team who owns the calendar") rather than a counting
challenge. Put any figure the issue leans on as a slot.

## Blog article

Owns the article's structure and the sentence-level craft. Cluster strategy, keyword assignment and
which page should win a query are keyword-guard's; ask for them rather than teaching them here.

```
WORKING TITLE       Two options, descriptive. Final title and meta follow the target query the
                    user or keyword-guard sets.
INTRO               Answer the question in the first paragraph, then say what the article adds.
H2 SKELETON         One heading per reader question, in the order a reader asks them.
BODY                Evidence under each heading. Quote slot: [source — fetch and date it].
INTERNAL LINKS      Placeholder list, one line each:
                    <anchor text> -> [page — supply URL]
                    ...
OPT-IN BLOCK        What the subscriber gets, in one line, plus the form slot.
```

Rules: write the answer before the story. Headings must be questions or tasks a reader would type,
not clever labels. Any factual claim needs the user's material or a source fetched in the session
with a date. Keep the internal-link list to pages the user confirmed exist, and flag any slot for a
page that does not yet exist, since that is the point where clusters and cannibalization get decided
elsewhere.

## Podcast outline

```
COLD OPEN           A clip or a line from later in the episode, transcribed, plus its timecode.
INTRO               Who the guest is in the user's own words, what the episode answers.
SEGMENT MAP         Timed blocks with the point of each, not a list of topics.
QUESTION BANK       Order the questions so each answer sets up the next. Mark the two that must
                    be asked. Write follow-ups for the likely answers.
TRANSITIONS         One written line between segments; this is what removes the dead air.
AD SLOTS            [sponsor line — supply this], placed at natural breaks.
OUTRO               The takeaway the host says aloud, then one CTA.
```

Craft notes: no filler means every segment has a named takeaway, and a segment without one is cut
before recording. Prepare the transitions and the first question in full; leave the rest as prompts
so the conversation stays live. Flag any claim the guest makes as unverified rather than repeating it
as fact in the show notes.

## CTA patterns by platform

X thread: bookmark-worthy recap then one action, commonly a reply, a follow or a link in the final
post. LinkedIn: name the reader and the next step, in-post or as a first comment, and test which.
YouTube: one ask after the payoff, tied to the video the viewer just finished. Short-form: the last
line is either the loop or the ask, never both. Instagram: one action per caption, and it must be
possible on the platform. Newsletter: one CTA per issue, with the benefit stated in the same sentence
as the link. Blog: an opt-in block with a specific promise, plus a next-read link.

Phrasing rule for all of them: state the reader's action and what happens next for them. Do not
attach a claimed outcome. Where a CTA choice is genuinely open, write it as a test:

```
TEST   Run <variant A> against <variant B> for <n> posts, compare <metric the user can see>.
       Baseline: [supply this]. Decide on the numbers, not on this document's guess.
```
